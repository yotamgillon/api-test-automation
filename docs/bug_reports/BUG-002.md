# BUG-002: Missing order returns 200 instead of 404

| Field | Value |
|---|---|
| Severity | Medium |
| Why | Clients cannot tell a missing order from a real one by status code, but no data is damaged. |
| Component | `GET /orders/{id}` (API) |
| Environment | `BUGGY_MODE=BUG-002` (also on with `BUGGY_MODE=1`), local uvicorn, Python 3.13 |
| Requirement | REQ-005 (reading a missing order returns 404) |

## Steps to reproduce
1. Start the app with `BUGGY_MODE=BUG-002 make run` on a fresh start, so no orders exist.
2. `curl -i localhost:8000/orders/DOES-NOT-EXIST`

To run the reproduction script from the repo root (it starts the app itself): `bash docs/bug_reports/repro/BUG-002.sh`

## Expected
HTTP 404 with `{"detail":"order not found"}`.

## Actual
HTTP 200 with the same body `{"detail":"order not found"}`. The body looks like an error but the status code says success.

## Evidence
Raw output from the reproduction (`results/evidence/BUG-002_repro.txt`, date and server headers left out here):

```
$ curl -s -i http://127.0.0.1:8802/orders/DOES-NOT-EXIST
HTTP/1.1 200 OK
{"detail":"order not found"}
```

Dedicated test, run with `BUGGY_MODE=BUG-002` (`results/evidence/BUG-002_test.txt`):

```
tests/api/test_orders_negative.py::test_bug002_get_missing_order_returns_404
E   assert 200 == 404
```

The 4 tests that fail with only this bug on are in `results/by_bug/BUG-002.txt`. Three of them (`test_delete_then_get_returns_404`, the `404-get` error-schema case and `test_delete_returns_204_and_removes_only_that_order`) fail because they read a deleted or missing order. This bug is not visible in the UI, which never fetches a single order.
