# BUG-001: Order accepted with zero or negative quantity

| Field | Value |
|---|---|
| Severity | High |
| Why | Invalid data is stored as a valid order, which would corrupt stock and billing downstream. |
| Component | `POST /orders`, `PUT /orders/{id}` (API) |
| Environment | `BUGGY_MODE=BUG-001` (also on with `BUGGY_MODE=1`), local uvicorn, Python 3.13 |
| Requirement | REQ-003 (quantity is an integer from 1 to 100) |

## Steps to reproduce
1. Start the app with `BUGGY_MODE=BUG-001 make run`.
2. `curl -i -X POST localhost:8000/orders -H "Content-Type: application/json" -d '{"customer":"Ann","item":"Pen","quantity":-5}'`
3. `curl -i localhost:8000/orders/ORD-0001`

To run the reproduction script from the repo root (it starts the app itself): `bash docs/bug_reports/repro/BUG-001.sh`

## Expected
HTTP 422 with a message saying quantity must be between 1 and 100. No order is created.

## Actual
HTTP 201. The order is created and can be read back with quantity -5. Zero is also accepted. The upper bound (101) is still rejected.
