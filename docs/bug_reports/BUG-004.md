# BUG-004: Invalid status transitions are accepted

| Field | Value |
|---|---|
| Severity | High |
| Why | A new, unpaid order can be marked delivered, and finished orders can be reopened, which breaks the core business rule. |
| Component | `PUT /orders/{id}` (API) |
| Environment | `BUGGY_MODE=BUG-004` (also on with `BUGGY_MODE=1`), local uvicorn, Python 3.13 |
| Requirement | REQ-008 (only new -> paid or cancelled, paid -> shipped or cancelled, shipped -> delivered) |

## Steps to reproduce
1. Start the app with `BUGGY_MODE=BUG-004 make run` on a fresh start, so no orders exist.
2. `curl -X POST localhost:8000/orders -H "Content-Type: application/json" -d '{"customer":"Ann","item":"Pen","quantity":1}'`
3. `curl -i -X PUT localhost:8000/orders/ORD-0001 -H "Content-Type: application/json" -d '{"status":"delivered"}'`

To run the reproduction script from the repo root (it starts the app itself): `bash docs/bug_reports/repro/BUG-004.sh`

## Expected
HTTP 409 and the order stays `new`.

## Actual
HTTP 200 and the order is now `delivered`. All 15 forbidden transitions are accepted, for example `delivered -> new` and `cancelled -> paid`.
