# BUG-003: Order list drops the last order

| Field | Value |
|---|---|
| Severity | High |
| Why | The newest order is missing from every listing, so users and the UI never see it. |
| Component | `GET /orders` (API), and the table in the UI that is built from it |
| Environment | `BUGGY_MODE=BUG-003` (also on with `BUGGY_MODE=1`), local uvicorn, Python 3.13 |
| Requirement | REQ-006 (the list returns every order in creation order) |

## Steps to reproduce
1. Start the app with `BUGGY_MODE=BUG-003 make run` on a fresh start, so no orders exist.
2. Create three orders with `POST /orders` (customers C1, C2, C3).
3. `curl -i localhost:8000/orders`

To run the reproduction script from the repo root (it starts the app itself): `bash docs/bug_reports/repro/BUG-003.sh`

## Expected
A list with 3 orders: ORD-0001, ORD-0002, ORD-0003.

## Actual
A list with 2 orders. ORD-0003 is missing, although `POST` returned 201 for it. In the UI, a single new order never appears in the table.

## Evidence
Raw output from the reproduction (`results/evidence/BUG-003_repro.txt`):

```
$ curl -s -X POST ... -d {"customer":"C3","item":"Pen","quantity":3} http://127.0.0.1:8803/orders
{"id":"ORD-0003","customer":"C3","item":"Pen","quantity":3,"status":"new"}
$ curl -s http://127.0.0.1:8803/orders
[{"id":"ORD-0001","customer":"C1","item":"Pen","quantity":1,"status":"new"},{"id":"ORD-0002","customer":"C2","item":"Pen","quantity":2,"status":"new"}]
```

Dedicated test, run with `BUGGY_MODE=BUG-003` (`results/evidence/BUG-003_test.txt`):

```

```
